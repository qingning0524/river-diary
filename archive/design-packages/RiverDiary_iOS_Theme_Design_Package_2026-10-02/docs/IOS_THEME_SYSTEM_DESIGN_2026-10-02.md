## 1. 产品决定与文稿边界

河流日记提供十套完整的手机界面主题。用户选择自己喜欢的阅读方式，照片、地点、活动、文字与 River 的理解随之换一种呈现。主题覆盖字体、色彩、表面、组件、插画和页面布局。

**已确认的范围**：十版全部纳入；用户可以自由切换；保留每版的主要视觉特点与内容组织方式。主题功能以 iOS 为第一实施平台。

**本文的实施默认方案**：十款内置且可直接使用；默认“河流手记”；外观默认跟随系统；偏好保存在本机；统一核心导航；切换即时生效并支持撤销。这些是本次文稿给出的具体设计方案。

当前十张参考图各有两个页面，共二十个示意画面。它们确定了方向，正式实施仍须补齐所有页面、浅深色、大字号、空状态、权限不足和错误状态。原稿中的人物、地点、照片与数字均为示例。

交付包含本设计文稿、主题目录 JSON、带十版参考图的 PDF。文稿只描述手机主题；现有 Mac 视觉体系及账号后端继续按各自的设计与数据契约工作。

## 2. 用户得到的体验

- 一眼看懂今天发生了什么：活动先聚合成生活片段，再按主题组织。
- 选择自己舒服的界面：喜欢纸质手记、地图、照片、周刊或极简风格，都能获得完整功能。
- 切换时继续刚才的操作：日期、正在看的记录、地图选点、阅读位置和未提交文字均被保留。
- AI 自然出现在相关片段中：可以展开依据、补充和纠正；主题不会制造新的推测或问题。
- 主题离线可用，选择过程中不用下载字体、重新登录或重新授予权限。

所有主题显示同一份生活事实、同一份有效的 AI 理解和同一份用户记录。不同主题可以调整视觉重点与组织形式，但记录的时间、身份、来源和确定程度保持一致。

## 3. 全主题的产品结构

### 3.1 稳定的四个主入口

本文建议统一为 **今天 / 足迹 / River / 我的**。主入口名称、顺序与目的固定，图标笔触、选中样式、色彩和栏的形态随主题变化。

| 入口 | 用户来这里做什么 | 内部能力 |
| --- | --- | --- |
| 今天 | 快速看懂一天、补上一条记录 | 生活片段、健康汇总、照片、日记、日历、日/周回顾 |
| 足迹 | 回想在哪里做了什么 | 真实位置、地点故事、对应活动、地点纠正 |
| River | 看理解、提问、补充与纠正 | 今日理解、上下文对话、可选确认、依据与相关记忆 |
| 我的 | 看长期回忆、管理个人偏好 | 回忆、项目、人物、地点、习惯、账号、主题、隐私与设置 |

草图中“胶片”“星图”“本周”“收藏”等特色名称作为页面内栏目保留，分别进入共享的回忆、周回顾和记录详情。每个主题都有清楚的“记一句”入口；不以一个巨大的加号取代主导航。

### 3.2 与当前工程的衔接

当前运行时主导航为 **今天 / 足迹 / River / 我的**。确认队列作为 River 内的二级页面打开；问题路由及回答、撤销、共享状态链路保持原有数据身份。主题入口位于“我的”和“设置”的外观区域。

确认提醒按价值进入相关活动或 River。没有问题时不显示占位任务；已回答或另一设备已解决的问题及时关闭。主题切换不能生成确认问题，也不能改变问题的答案。

“生活周刊”的本周、“日子花园”的日历和“随身剪贴簿”的收藏，都是稳定能力的特色呈现。切换后仍能找到同一条记录，返回时仍位于原来的日期与上下文。

### 3.3 覆盖范围

完整覆盖六类主场景：今天、足迹、River、我的/回忆、记录详情、主题选择。二级场景包括提问与回答、记忆纠正、手写输入、账号、兑换码、设置、权限说明、系统提示和错误反馈。

系统授权弹窗、照片选择器、分享面板等使用原生组件；可采用主题色，但保留系统的操作方式和无障碍行为。

## 4. 十个主题的设计契约

十个主题在同一份数据上使用十种呈现方式。下表中的参考外观指原稿的主要观感；正式运行的浅深色由用户的外观设置决定。

| 编号 / 稳定 ID | 主题 | 主要表达 | 参考外观 |
| --- | --- | --- | --- |
| 01 / `river_journal` | 河流手记 | 纸质手记、章节与文学排版 | 浅色 |
| 02 / `city_roamer` | 城市漫游 | 地图优先、地点与生活故事 | 浅色 |
| 03 / `time_film` | 时光胶片 | 深色胶片、影像和时间带 | 深色 |
| 04 / `light_everyday` | 轻盈日常 | 清晰平面、连续生活流 | 浅色 |
| 05 / `life_constellation` | 生活星图 | 活动与记忆的关联 | 深色 |
| 06 / `day_garden` | 日子花园 | 自然气息、温柔生活章节 | 浅色 |
| 07 / `life_weekly` | 生活周刊 | 私人刊物、日/周阅读 | 浅色 |
| 08 / `tidal_clock` | 潮汐时钟 | 一天的时间分布与节奏 | 深色 |
| 09 / `pocket_scrapbook` | 随身剪贴簿 | 纸张、照片与短句收藏 | 浅色 |
| 10 / `pure_life` | 纯净生活 | 简明片段、上下文理解 | 浅色 |

### 01 河流手记

暖象牙纸、墨绿、细分隔线与衬线标题。留白像书页，时间是页边注，活动按早晨、午间、傍晚、夜晚形成章节。正文保持清楚的字号与行距，长段落不强制使用装饰字体。

今天采用“日标题 - 一句理解 - 生活章节”；详情采用景象、事实、用户文字和可展开理解的阅读页。足迹中的地点成为沿途章节；River 像页边的一条温和批注；回忆按日期与专题装订。保留“手记”气质，所有页面的纸张层级与文字色统一。

### 02 城市漫游

浅石灰、钴蓝、清楚的窄体数字与地图标注。今天以地图和下方地点故事为主；片段与真实地点互相定位。选中地点后，打开对应时间范围中的照片、餐食、活动和文字。

足迹强化地图与故事联动；River 的理解引用地点与相关活动；回忆可按地点浏览。地图加载失败、位置权限关闭或精度不足时，仍提供已保存的生活片段。只记录停留点时显示位置线索，不绘制看似精确的连续路线。

### 03 时光胶片

炭黑、琥珀和少量铁锈橘。照片是主视觉，活动像一帧帧胶片，时间带承担快速定位；文字清楚地叠放在可读的实体表面上。

详情以画面和记录文字展开；足迹使用“地点旁的帧”关联照片；River 是可展开的旁白；回忆使用真实照片形成胶片卷。无照片时以可读的文字片段承接，插画仅作装饰。深色辅助文字和未选中导航也须可读。

### 04 轻盈日常

干净白、珊瑚红、几何无衬线与利落的数字。日期明确，生活片段沿一条连续时间流排列，健康信息作为简短汇总出现，核心动作容易找到。

足迹以简洁地图和短列表表达；River 以短句、引用与展开项表达；回忆用清楚的列表和日期索引。详情先回答做了什么、持续多久、来自哪里。珊瑚色用作视觉重点，按钮采用达到对比要求的交互色。

### 05 生活星图

午夜蓝、柔和鸢尾紫、细线和星点。活动是可点击的节点，关联是有依据的连线；文字阅读顺序优先于图形装饰。

今天的星图只组织已存在的活动；River 与回忆展示实际关联。足迹仍呈现真实地理位置，避免把星图当作地图。节点数量多时聚合并提供列表；大字号、VoiceOver 或减弱动态效果下使用相同内容的有序列表。没有关联证据时不绘制具有关系含义的连线。

### 06 日子花园

青瓷、陶土色、圆润标题和少量植物/晨光插画。一天通过几幕生活慢慢展开，氛围温柔，记录按钮具有清楚的触控边界。

今天按生活章节组织；足迹像简洁的沿途路书；River 是局部的理解段落；回忆使用日历与生活章节。植物是静态装饰，不与活跃天数、健康分数或用户表现绑定，不制造“花枯了”“今天不够好”等压力。

### 07 生活周刊

蛋壳白、朱红、极粗标题与刊物式分栏。日标题有鲜明的日期，重点片段像当天的头条，其余片段保留真实时间；每周回顾形成私人刊物。

详情像短篇文章；足迹像城市栏目；River 的理解有明确署名与依据；回忆按日/周刊组织。标题优先采用用户文字或事实性标题。分栏在小屏和大字号时自动变成单栏；周刊使用已有的周记录与回顾，不为主题切换重新调用 AI。

### 08 潮汐时钟

深海青、浅水青、精细刻度与稳重标题。圆形一天时钟呈现有明确时间范围的活动，点开时段后进入生活故事。

详情连接时段、照片、实际时长与地点；足迹强调活动时间与位置的配对；River 梳理记录中的节奏；回忆显示有证据的日/周时间分布。缺记录的区间以未知表达，日累计步数等不放到零点。时钟不是生活评分器，休息与留白不被标为低效。

### 09 随身剪贴簿

暖羊皮纸、深梅紫、少量楷书/手写感与轻微错位的照片。文字和图片像被贴进个人收藏页，照片角度和纸张层次克制使用。

今天以照片、短句与活动组成纸页；详情允许继续补写；足迹成为地点明信片；River 的理解有独立署名；回忆按收藏与主题组织。用户原文和 AI 文案通过标题与标签区分。长文字、大字号和阅读辅助模式恢复直立、单栏的清楚布局。

### 10 纯净生活

冷瓷白、黑墨和青柠。当天重点、两个主要片段与其他活动形成清楚的主次；短句理解紧贴相关片段。

今天使用片段双栏与紧凑摘要；足迹用简洁地图和地点条目；River 使用清楚的事实引用与可展开解释；回忆使用安静的卡片与列表。双栏在较大文字尺寸下变为单栏。主按钮与输入框始终可发现，克制使用大色块。

## 5. 主题选择与切换流程

### 5.1 明确入口

入口为“我的 - 设置 - 外观与主题”。我的页面另提供一行当前主题摘要，例如“河流手记 · 跟随系统”，点击进入同一选择页。账号登录页也采用已保存主题，并提供一个轻量的外观入口。

主题选择页使用两列静态预览卡。十版按 01-10 固定排序，标题与一句风格说明常驻。当前主题以“正在使用”和勾选图标表达，颜色作为辅助。搜索不是首版必需；简短分类只辅助浏览，默认显示全部十版。

卡片预览使用明确标记的示例内容。页面可提供浅/深色切换查看预览；卡片采用缩略图，详情仅挂载当前预览的一套页面。示例不会写入用户记录库，也不会发送给 AI。

### 5.2 外观偏好

外观选择为“跟随系统 / 浅色 / 深色”，默认跟随系统。每个主题都提供浅深色定义。选择另一个主题时保留这项外观偏好。

十版原稿的主要观感作为视觉参考。深色胶片的浅色版本保留琥珀、影像层级和胶片形态；浅色手记的深色版本保留纸张层次、衬线与墨绿气质。暗色页面不会通过整页反色生成。

### 5.3 预览、应用与撤销

1. 点击卡片进入主题详情，展示主题名字、风格说明、今天/详情预览和浅深色表现。
2. 预览只修改候选状态，应用当前主题的页面保持可恢复；关闭预览直接回到选择页。
3. 点击“使用此主题”，验证主题定义后提交本机偏好并更新可见页面。
4. 显示“已切换为城市漫游”，同时提供五秒的“撤销”。保持原来的页面、日期与记录上下文。
5. 选择当前主题时主按钮显示“正在使用”，不重复触发刷新。
6. 连续选择时以最近一次明确点击的主题为准；撤销只撤销最后一次已应用的选择。

切换采用短暂、克制的淡入，目标约 180 毫秒；减弱动态效果时直接替换。后台记录、同步和正在进行的 AI 分析继续处理自己的数据，主题不触发这些任务。

### 5.4 切换时保留什么

| 状态 | 保留规则 |
| --- | --- |
| 页面与详情路由 | 按语义页面和对象 ID 保留，详情继续显示同一条记录 |
| 日期与范围 | 保留所选日、周和月份，不自动跳回今天 |
| 阅读位置 | 以活动/记忆 ID 作为滚动锚点；新布局中恢复到同一对象 |
| 地图 | 保留地图视区、选中地点和对应时间范围 |
| 输入 | 保留未提交的日记、补充、纠正和聊天草稿 |
| 外观与辅助设置 | 保留浅深色选择，响应系统字体、对比度和减弱动态效果 |

应用失败时继续使用原主题并显示原因与重试入口。未知或过期主题 ID 回退至“河流手记”，用户数据和输入草稿仍保留。

## 6. 全局组件与视觉变量

### 6.1 语义化视觉变量

页面通过“这个颜色用来做什么”取值，而不是自行写色值。主题定义两组浅深色基础变量，并由组件获取颜色、字体、间距和形状。

| 类型 | 必备变量 / 规则 |
| --- | --- |
| 颜色 | canvas、surface、raisedSurface、ink、secondaryInk、accent、onAccent、separator |
| 特殊表面 | riverSurface、placeSurface、noteSurface，保持文字对比与来源区分 |
| 字体 | 页面标题、章节标题、正文、说明、按钮、等宽时间与数字 |
| 空间 | 页边距、章节间距、段落间距、组件内边距；随大字号增高 |
| 形状 | 普通面板、照片、输入、按钮、浮层与地图的圆角/描边 |
| 装饰 | 插画、纸张、胶片、星点、刻度；拥有明确的装饰语义 |
| 动效 | 反馈、主题切换、展开收起；遵循系统辅助设置 |

目录 JSON 提供 V1 色彩与布局起点，标记为设计目标，不是已接入的运行时配置。原稿的种子色与可交互色可以不同：例如珊瑚色保留在装饰上，按钮使用更深的珊瑚色。

正文建议基础字号 16 pt，辅助文字 13 pt，页面标题 28-34 pt，按钮标题 15-17 pt；这些是随 Dynamic Type 缩放的基线。中文衬线与手写风格以可用字体与真机显示为准，字体缺失时使用系统回退，避免为了主题在运行时下载字体。

### 6.2 核心组件

统一组件覆盖：日期控制、生活片段、照片、餐食估算、健康汇总、地点故事、River 理解、事实/推断标签、记录输入、确认选项、错误提示、导航和主题卡。

布局有特色，交互有共通性。点击活动进入同一详情；所有 AI 理解都能看依据与更正；记录入口具有相同的保存语义；危险操作保持明确的说明与确认。

## 7. 事实、未知和系统状态

主题使用三类明确信息标签：已记录的事实、River 的暂定理解、用户写下/确认的内容。未知使用文字直接说明，颜色与图标只提供辅助。

| 情况 | 全主题的表达 |
| --- | --- |
| 没有生活记录 | “今天还没有记录。你可以先留下一句话。”提供一个记录入口 |
| 没有照片或仅有部分照片权限 | 使用文字片段与明确占位；不插入示例照片充当生活事实 |
| 没有位置权限 | 已保存内容可读；地图区域说明如何开启，授权由用户点击发起 |
| 位置精度不足 | 显示系统估计误差，地点写“可能是”；避免精确商户断言 |
| 仅有位置点 | 标为位置线索；不显示未经记录的连续路线或交通工具 |
| 日累计步数、健康汇总 | 放在日汇总区域；没有明确时间范围的统计不放到 00:00 |
| 餐食分析 | 标明估算范围、份量未知及来源；主题不能改写为精确热量 |
| AI 未启用、正在分析、失败 | 本机生活记录仍可读；对应理解区域显示准确状态和可执行操作 |
| 已回答、同步中、另一端已解决 | 显示实际保存与同步阶段，使用同一确认状态 |
| 离线或未登录 | 本机主题选择正常工作；账号相关操作按原有能力显示状态 |

当前单次高精度定位只接受系统误差半径不超过 100 米的位置；足迹选用一段内误差最小的坐标作为标点。主题沿用这些已有规则，不通过地图样式、插画或位置平均值改变坐标含义。

所有页面使用真实已保存的数据，不因主题变化填充不同的活动标题、自动写日记或制造“你很开心”“你经常去这里”等没有依据的结论。图稿的示例标题不能直接进入正式数据。

## 8. 可读性、辅助使用与流畅度

### 8.1 可读性与辅助使用

普通正文和辅助文字按至少 4.5:1 的对比目标设计，按钮文字与状态标签也纳入检查；浅深色分别验证。此目标与 Apple 的小字号文本建议一致。[Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)

本项目交互区域以至少 44 x 44 pt 为约束，保留系统安全区，键盘弹起时保存、完成与返回操作仍可达。图片中的字不能替代真正的文字控件。

支持系统动态字号。双栏、周刊分栏、星图与拼贴在辅助字号时转为有序单栏；保留主题的色彩与标题特征，同时确保正文、按钮和来源标签完整可读。[Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)

VoiceOver 的顺序为日期、当天摘要、按时间组织的活动、主动记录、导航。星图连线和插画默认不朗读；有意义的节点读出时间、活动及状态。减弱动态效果和增强对比度覆盖所有十版。[Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)

### 8.2 针对已有卡顿问题的实现约束

- 主题切换只重算当前视觉环境及可见布局，不重新打开数据库、做全量排序、查询健康、解析照片、反向地理编码或请求 AI。
- 同一份已构建的日展示模型交给主题渲染；主题布局中不调用全量 `allEvents()`。
- 列表使用稳定对象 ID 与懒加载；图片按展示尺寸异步缩略和解码。
- 主题列表使用缓存缩略图，不同时构建十套真实今天页面；完整预览最多挂载一套。
- 不把十套主题页面都放在隐藏的 ZStack 中。日期、路由、草稿和滚动锚点由外部状态持有。
- 纸张、植物、胶片和星图优先静态矢量或缓存图层，避免持续循环动效、多层大面积模糊和逐条重影。

### 8.3 待实测的验收目标

以下是实施目标，不代表当前已经测得的结果。以用户正在使用的 iPhone 14 Pro 为主要基线，并补测项目最低支持的设备/系统。

| 指标 | 验收目标 |
| --- | --- |
| 已缓存主题的切换 | 点击到稳定显示 P95 不超过 250 ms；不含首次地图瓦片下载 |
| 滚动与连续操作 | 与同数据基线相比无明显退化；固定 60 Hz 条件检查帧耗时及超过 50 ms 的主线程停顿 |
| 主题预览内存 | 完整预览一次只保留一套；退出后内存趋于稳定，无持续增长 |
| 切换副作用 | 切换过程新增 AI 请求、定位请求和业务写操作均为零 |
| 稳定性 | 连续切换十版再切回，日期、路由、草稿、输入和地图选点保持正确 |

测量覆盖空记录、普通一天、密集照片及大量历史记录。记录所用数据量、图片规模、系统、构建和测量条件；达不到目标时先修复，再增加装饰效果。

## 9. SwiftUI 实施架构与当前状态

### 9.1 已实现

`Managers/RiverThemeStore.swift` 定义十个稳定 ID、浅深色语义色板、字号/留白/圆角上下文、本机偏好、应用与短时撤销。`RiverDiaryApp` 将主题环境和系统外观注入应用。主题目录 JSON 保留为设计参考，运行时定义以 Swift 源码为准。

`Views/RiverThemeSettingsView.swift` 提供十主题浏览、每版独立的今天/详情示例预览、跟随系统/浅色/深色选择、应用与撤销。`RiverThemeDayOverview` 和 `RiverTimelineActivityRow` 为十个主题分别提供纸页章节、位置地图、胶片帧、清洁流水、时间散点星图、花园章节、报纸头条、24 小时时钟、剪贴卡片和极简事实列表。电影/剪贴主题读取本机已授权照片；没有可用照片时明确显示带“插画”标签的主题插画。所有活动、时间和位置继续取自共享事实，不为视觉效果编造记录。

记录详情也按主题改变版式：实际坐标才显示地图、实际照片才进入照片框，其他主题分别采用手记边注、胶片封面、散点星图、花园札记、报纸文章、潮汐刻度、剪贴页或极简事实摘要。底栏保留四个稳定入口，但各主题有自己的图标和选中标记。今天、足迹、River、我的/记忆、日记、洞察、账号和设置使用主题语义色；主题切换继续使用共享事实和状态，不创建第二套业务数据。

主导航现为今天、足迹、River、我的；确认队列从 River 中打开。地图显示真实已保存的点位和精度范围，不绘制虚构的连续路线。胶片/剪贴簿主题读取用户已授权的本机照片缩略图，不上传或保存照片标识。

iOS 同步协调器先在主线程取得本机快照，再把 iCloud 复制目录的协调读写移到后台任务；首次启动不再等待 `NSFileCoordinator` 扫描。局域网复制初始化只负责启动监听，同步由异步任务执行。

### 9.2 运行时职责

| 模块 | 职责 |
| --- | --- |
| RiverThemeID / RiverThemeContext | 十个稳定 ID、浅深色语义色、字体比例、留白与组件形状 |
| RiverThemeStore | 当前偏好、示例预览、应用、撤销与本机持久化 |
| `riverTheme` 环境键 | 将当前主题上下文传给使用主题令牌的视图 |
| RiverThemeDayOverview | 根据十个主题 ID 选择不同的今日内容组织方式 |
| RiverThemeSettingsView | 浏览、预览、外观选择、应用和撤销 |
| RootView / RiverIOSRoute | 四个主入口以及 River 内确认队列路由 |

数据流：业务记录与有效理解 → 共享展示模型 → 当前主题布局 → 真实交互。主题偏好单独流向视觉环境。只允许业务交互进入原有写入/纠正链路。

运行时主题通过源码定义，不读取设计目录 JSON。主场景及可从设置进入的日记、记录详情、洞察、账号和设置子面板均已接入主题版式或语义色；错误、成功和记录阶段仍按其信息含义显示状态色。荧光色主题将正文小字和图标使用更深的对比色，亮色只用于强调面和较大的装饰。

### 9.3 状态与身份

`themeID` 使用稳定英文 ID，编号 01-10 仅为展示顺序。页面和对象身份沿用稳定的日期、活动、地点、问题与记忆标识。

避免在 RootView、NavigationStack 或数据存储对象上设置 `.id(themeID)` 以强制重建。允许叶子布局变化，但须在变化前记录语义锚点，再恢复到同一条活动。星图、分栏或照片流可使用不同的呈现顺序；依然要提供按时间的完整列表。

### 9.4 偏好格式

拟定偏好内容为 `schemaVersion=1`、`themeID=river_journal`、`appearance=system`。外观只接受 `system / light / dark`。首版无需账号服务器接口。

使用单个可编码的小型本机偏好记录保存，避免主题与外观分别更新形成中间状态。编码失败或主题定义不可用时不提交候选值。启动时未知 ID/版本回退至默认，保留旧值用于迁移诊断；不能清理业务记录。

切换反馈只表示本机主题已应用。主题首版本机独立；若将来增加跨设备主题偏好，需提供明确开关，并通过既有加密共享设置链路实施，不将 iPhone 的布局直接应用到 Mac。
