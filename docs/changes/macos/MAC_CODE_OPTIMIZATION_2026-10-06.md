# Mac 数据读写与记忆刷新优化 · 2026-10-06

本轮优化用户决定的保存/导入查重、记忆依据装配和大批量 ID 查询。复用当前 SwiftUI、V2Store 和 SQLCipher，数据模型、共享协议及事务边界保持兼容。

## 代码变化

| 位置 | 原有开销或问题 | 调整 |
|---|---|---|
| [V2Store](../../../macos/RiverDiaryMac/Sources/RiverDiaryMac/Infrastructure/Database/V2Store.swift) 的本地操作与远端导入 | 每条待写记录都读取并解码完整操作历史，再查找相同 ID | 按 `operation_id` 主键查询；单条和全量查询复用同一解码逻辑 |
| V2Store 的片段与记忆确认批量读取 | 重复 ID 占用查询参数；超过 SQLite 连接参数上限时会返回空结果 | ID 去重，按当前连接上限分批，每批最多 400 个；任何一批失败时不返回部分结果，并记录错误 |
| [MemoryLibrary](../../../macos/RiverDiaryMac/Sources/RiverDiaryMac/Features/Memory/MemoryLibrary.swift) 的来源装配 | 每条记忆遍历全部关联片段，装配成本为记忆数乘以片段数 | 一次建立 ID 索引，再读取各记忆实际引用；重复引用去重，缺失引用跳过 |
| 片段读取与展示排序 | 起始时间相同时排序未指定 | 起始时间优先，相同时间按 UUID 排序，批次和输入顺序不影响结果 |

记忆来源装配的索引与查找工作从 `O(M × E)` 降为 `O(E + R)`，其中 M 为记忆数、E 为已取回的片段数、R 为去重后的关联数量；每条记忆的时间排序仍保留。索引每次刷新重建，编辑记忆来源后不会沿用旧关联。

## 验证证据

新增 7 项回归验证，Mac 全量 **398 项隔离测试通过，0 失败**。

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 256 条历史下保存 32 条新用户决定并重试 | SQLite 全表扫描步进 17,840 次 | 0 次；重试返回原操作，序号与 frontier 不增加 |
| 同一历史量下导入并从另一传输重试 32 条操作 | SQLite 全表扫描步进 17,840 次 | 0 次；内容不重复，导入 frontier 正确 |
| 连接参数上限设为 8，读取 24 条片段，包含重复和缺失 ID | 返回空数组 | 完整返回 24 条片段，按时间排序 |
| 相同上限下读取 24 条记忆确认 | 原路径无法容纳该数量参数 | 确认/否认状态和备注完整返回 |
| 同批导入中，后续操作与已有 ID 冲突 | 需要保持原有原子性 | 先写入的操作、导入登记和 frontier 一起回滚 |
| 两条记忆共享片段，含重复和缺失来源 | 需要保持依据归属 | 来源不重复、不串到其他记忆，缺失来源跳过 |
| 更新记忆来源后再次刷新 | 需要避免旧索引残留 | 新来源替换旧来源 |

扫描指标来自 SQLCipher 的 `sqlite3_trace_v2` 与 `SQLITE_STMTSTATUS_FULLSCAN_STEP`，测量实际查询工作量，不依赖机器负载造成的计时波动。它描述查重路径，不代表整个同步链路的所有扫描均已消除。

原有本地保存冲突回滚、加密复制、分析产物失效、草稿、账号与界面测试随全量套件通过。Release 构建及本地应用打包通过，应用签名、SQLCipher 框架和运行时加载路径校验通过。结果同时记录在 [开发验证记录](../../validation/DEV_BUILD_STATUS.md)。

验证使用专用临时应用数据目录。原始日记、项目快照、平台内置数据、每日输出与官网发布下载共 56 个文件的内容校验值未变。当前 [Mac 应用](../../../dist/River%20Diary.app) 已更新为本轮 Release 构建；原包保存在 `archive/releases/macos/RiverDiary-macOS-before-code-optimization-20261006.zip`，归档中的 16 份普通文件与原包摘要完全匹配。未启动正式应用或调用数据同步构建。
