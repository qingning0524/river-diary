# 用户加密云空间 · 变更记录（2026-10-20）

## 为什么

用户希望可以自行决定把记忆副本上传到云空间，以便在另一台设备查看。原架构默认由账号服务保存身份、设备、权益与反馈，不接收日记正文。此次不把默认边界改成“服务端可读日记”，而是增加一个**显式开启、端到端加密、可单独删除**的只读快照：浏览器加密，服务端只存密文。

## 用户路径

1. 登录记忆控制台 → 账号与设置 → 云空间。
2. 输入至少 12 个字符的云端口令，再次确认，勾选“理解口令丢失无法恢复”。
3. 点击“加密并上传”，浏览器用 PBKDF2-SHA-256（600,000 次）+ AES-GCM-256 加密当前只读副本，再上传密文。
4. 另一台设备登录同一账号，进入云空间，输入同一口令，下载并在本机解密。
5. 可单独删除云副本；删除本机副本不影响云副本，账号注销级联删除云副本。

默认不开启、不自动上传、不自动合并。多端是手动快照；替换用 `If-Match` 防止静默覆盖。

## 服务端

- 迁移 `0012_user_memory_mirrors`：`user_memory_mirrors` 表，`user_id` 主键、`ON DELETE CASCADE`、密文 bytea、KDF/IV/摘要/修订。
- `server/internal/httpapi/memory_mirror.go`：
  - `GET /v1/me/memory-mirror/meta`
  - `GET/PUT/DELETE /v1/me/memory-mirror`
  - 密文 16 MB、请求 24 MB、摘要白名单、盐/IV/迭代次数校验、`If-None-Match`/`If-Match`、审计与用户隔离。
- `server/cmd/api/main.go`：API 读/写超时从 10/15 秒调整为 45/45 秒，保留 5 秒头部超时与 32 KB 头部上限。
- `server/api/openapi.yaml`、`server/README.md`：契约与边界。

## 隐私与文案

- 控制台隐私对话框、首页、账号概览、`website/site/privacy.html` 和官网云服务说明均改为“默认不上传；只有主动开启云空间时服务器保存不可解密文”。
- 未把云空间写成默认能力、自动同步或服务端可读。
- 服务端不保存口令；口令丢失无法恢复，不能由服务端重置。

## 后续修正（2026-10-20）

“写一句”本机速记只写入当前标签页，既不进入原生库，也不能多端查看，容易让用户误以为网页端可以编辑日记。该入口、对话框、样式与测试已移除；控制台保持只读，空态改为“导入 JSON / 从云空间恢复”，并明确标注原生导出入口仍在接入（T12）。
