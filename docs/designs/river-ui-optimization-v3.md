## 1. 设计方向

保留用户参考图确立的暖纸色、石墨文字、钢蓝强调色与左侧日期导航。把它发展为安静、易读、可追溯的个人记忆工作台。

首页要在十秒内回答：这一天主要发生了什么、已知多少、哪些内容值得追问。时间线负责过程；右侧证据详情负责解释与修正；进展负责可比较的变化。采集状态统一在左侧导航下方，页面只在数据缺失直接影响当前内容时给出针对性说明。

日期切换统一在左侧。主内容日期可以作为只读标题；周期页面使用左侧日期作为截止日，自己的周期控件只负责长度，不另设一套日期导航。

## 2. 当前问题与改进目标

| 当前表现 | 对使用的影响 | 优化方向 |
|---|---|---|
| 大量 8–10pt 状态、英文小标题与淡灰说明 | 重要信息难读，界面显得像缩小的管理后台 | 正文、标签、状态分级增大，减少英文眉题 |
| 首页摘要是跨越整页的长段文字 | 找不到当天的重点，阅读时频繁横向扫视 | 一句结论、最多三条重点、单独的覆盖说明 |
| 卡片大面积留空，但信息挤在左上角 | 空间充足仍有拥挤感 | 根据内容设置内边距和高度，减少无意义等高卡片 |
| 首页、时间线、进展的内容起点和宽度不同 | 切页像进入不同应用 | 统一页面容器、标题栏和组件尺度 |
| 顶部工具图标和页面眉题过近 | 工具栏、窗口拖动区域与内容层级混淆 | 保留原生工具栏安全区域，正文从其下方开始 |
| 时间线前面放着大块空白写作区 | 用户进入页面不能立即看到过程 | 写作成为明确入口，编辑时展开或打开专用面板 |
| 时间线以应用切换片段为主，重复名称与来源较多 | 数据很多但难以回顾一天 | 默认浏览有依据的事件段，原始片段按需展开 |
| 进展页面是七张近似卡片 | 有数字，缺少趋势；覆盖不足不够突出 | 趋势图、覆盖天数、对照表和证据例子结合 |
| 设置页双侧栏加宽表单，开关与路径散布 | 扫描费力，普通操作被技术信息包围 | 四个明确设置分区与一致表单行；技术细节折叠 |
| 同屏总时长与摘要时长有差异 | 无法判断哪个数字应被信任 | 明确已保存片段和当前进行中的片段，并统一统计快照 |
| 证据百分比没有清楚含义 | 容易把采集完整性理解为结论正确概率 | 优先写覆盖范围、缺失来源、判断依据，解释百分比口径 |

## 3. 全局布局

### 3.1 三个区域

```text
左侧导航 224pt       中央内容，按页面选择宽度         证据详情 320–360pt
品牌与日期           页面标题 + 页面操作              记录标题 / 时间
分组导航             摘要 / 列表 / 趋势               原始来源
                     选中内容与详情联动               解释与不确定性
采集状态             页面级滚动                       人工修正
```

- 侧栏默认 224pt，允许约 208–280pt 调整；导航行高 32–36pt。
- 内容横向边距建议 28–32pt；同类页面保持相同左边界。
- 阅读型内容最大宽度约 880–960pt；日记长文约 680–760pt；数据库表格可更宽。
- 1320pt 及以上可并排显示侧栏、内容、证据详情；主内容不足约 640pt 时关闭并排模式。
- 960–1319pt 默认双栏，证据详情通过原生浮层或面板打开；不要把正文挤成过窄列。
- 在当前最小窗口 960×640 下，核心操作不需要水平滚动；卡片变为单列或紧凑行。
- 工具栏保持固定高度和原生拖动区域。禁止以忽略安全区域的方式把页标题顶入工具栏。
- 导航、主内容、证据详情可独立滚动；每个区域内部只设一个主要纵向滚动容器。

### 3.2 左侧导航

保留全部现有功能，统一为中文分组：

- 一天：今日总览、时间线、每日复盘。
- 生活：健康、足迹、学习与工作。
- 记忆：记忆库、询问、进展。
- 系统：数据库、数据源、设置。

选中项使用浅蓝底、清楚的文字与细左边标识。SF Symbols 使用统一大小和粗细，不增加装饰图标。

日期区提供当前日期、星期、前后一天、返回今天、日历弹层。跨页保留所选日期。今日总览在历史日期下改为“当天总览”等上下文文案。

状态始终在导航下方。正常情况下显示总体状态和各来源的短状态；展开可以看到上次成功采集、缺失原因与处理入口。短窗口允许状态区滚动，不能为了塞进所有内容把关键文字缩到 8pt。详细状态同时支持点击和键盘访问，不只依赖悬停。

## 4. 视觉规范

### 4.1 字体与密度

| 元素 | 建议规格 |
|---|---|
| 当天日期 / 主要页面标题 | 26–28pt / 22–24pt，semibold |
| 关键数值 | 26–32pt，等宽数字，单位较小 |
| 区块标题 | 15–16pt，semibold |
| 正文、结论、日记 | 14–15pt，长文行距约 1.45–1.6 |
| 导航和普通按钮 | 13–14pt |
| 来源、时间、说明 | 11–12pt，保留足够对比度 |
| 技术 ID | 11pt 等宽字体，仅详情中展示 |

中文与英文 UI 使用系统字体；时间与数值采用等宽数字。移除页面间不一致的衬线标题。提供“标准 / 紧凑”两种内容密度，紧凑模式主要减少间距，不压缩关键字号。

### 4.2 配色与表面

浅色基底沿用：画布 #F1F0EB、面板 #FBFAF7、文字 #252628、次级文字 #6F7072、分隔线 #D7D6D1、钢蓝 #466E9D、选中浅蓝 #E7EDF5。实际组合必须测量对比度，不能只按色值判断合格。

深色模式使用动态语义颜色：画布、面板、抬升表面逐级区分，正文接近暖白，蓝色与状态色单独适配；不能简单把浅色背景翻黑。增加跟随系统选项。

普通卡片建议 8–10pt 圆角、16–20pt 内边距；按钮高度 30–34pt；区域间距 24–28pt；相关内容间距 8–12pt。背景层级和留白优先，边框只帮助分组，阴影主要留给浮层。

统一按钮层级：每个视图一个主要动作；普通动作使用次级按钮；轻动作使用文字链接；图标操作必须有名称与提示。避免重复叠加自定义描边和系统按钮外框。

### 4.3 语义标签

事实来源使用“设备记录 / 导入记录 / 手动记录”；解释使用“AI 推测 / 已确认 / 待确认”；缺失状态使用“未接入 / 当天无数据 / 已过期 / 同步失败”。标签同时依靠文字和形状，不能只靠颜色。

“未知”“0”“未识别”须独立：没有测量不能显示零；有记录但无法分类要展示未分类时长；只有确认测得零值时才显示零。

## 5. 各页面设计

### 5.1 今日总览

阅读顺序为：日期与核心动作 → 当天简报 → 工作/地点两个主要入口 → 健康、娱乐、目标等紧凑事实 → 事件概览 → 待确认。

简报由一句结论和最多三条重点组成，每条可查看证据。无 AI 时提供清楚的本地事实版本；原始数据不足时明确缺什么，不拼出貌似完整的生活叙述。例文和原型中的人物行为、时长必须标注演示数据。

工作与学习卡展示已分类时长及未分类部分；地点卡展示最近或主要地点、停留和来源；健康、娱乐、目标使用可点击的紧凑模块。未接入来源使用小型连接提示，不占据与完整数据相同的大块空卡。

顶部保留一个“询问这一天”主动作。写日记与快记明确区分，支持继续上次草稿。日报长内容可展开和全文阅读，不能只被行数上限截断。

待确认显示数量与少量最有价值的条目，支持进入完整列表。没有窗口标题不应让所有片段都同等变成待处理任务。

### 5.2 时间线

进入页面即可看到事件；写日记按钮打开写作面板，已有日记显示简短预览。取消当前大块空编辑框对首屏的占用。

默认按有证据支持的连续活动组织事件段；只能确定应用时就写应用名，不能自动改写成“推进项目”。每段可展开原始片段、窗口标题和来源。归并规则可解释，跨来源冲突不强行合并。

每行包含固定宽度时间列、事件内容、相邻的来源标签与时长。去掉同一应用名在标题、摘要和来源中的无效重复；来源不要远离内容贴在页面最右边。持续时间小于一分钟且首尾分钟相同时显示秒级详情，避免“00:15–00:15”的歧义。

空档用紧凑虚线区分；未记录不能被当成睡眠或休息。筛选条包含全部、工作学习、娱乐、地点、手记、待确认，并有清除筛选入口。筛选后无结果与全天无记录采用不同空态。

### 5.3 证据详情

固定结构：标题与发生日期 → 来源及原始记录 → 解释为何得出判断 → 人工修正。明确关闭按钮，Esc 关闭并将焦点还给原条目。选中事件在时间线与详情中保持一致高亮。

来源要能定位到真实原始记录。编辑提供保存、取消和错误反馈；保存失败保留输入；保存后列表、摘要、足迹和询问中的人工信息保持一致。切换所选事件时不得把上一条的草稿写给新条目。

### 5.4 每日复盘

与时间线区分：时间线回答发生顺序，复盘回答这一天值得记住什么。默认跟随左侧所选日，提供事实摘要、目标进展、个人感受和补充记录。周期回顾、月度信作为独立可切换子视图，明确范围起止日期。

“保存复盘”“生成 AI 解读”“导出”各有明确作用。生成、个人编辑和重新生成不能互相无提示覆盖；保存版本可以追溯。

### 5.5 健康

用睡眠、活动、主观心情三个模块组织。主要指标带测量日期和来源，趋势按选定周期查看。主观心情始终标注“你记录的感受”。睡眠来源缺失时显示接入入口，不绘制零值趋势，也不推导医学结论。

### 5.6 足迹

仅展示真实地理地点：可选地图 + 当天到访列表 + 停留详情。每个地点包含到离时间、精度、来源、推断活动与修正入口。地图属于拟新增能力，不代表当前已实现。

未连接位置时展示清楚的接入步骤和手动补充；不得用电脑应用活动充当地点。展示地理推断时需区分原始定位点、归并停留与用户确认地点。

### 5.7 学习与工作

按项目、主题和证据组织，而非只按应用排名。区分应用时长、可识别工作片段、可验证产出、目标完成。浏览或 AI 聊天本身不足以确定生产效率。

显示未分类时间并提供分类修正入口；修正单条记录与建立长期分类规则需分开。图书馆停留和浏览/代码证据可以关联，推断要有来源标识。

### 5.8 记忆库

搜索固定在顶部，提供日期、类型、来源、收藏筛选。日期档案与长期主题分组呈现；结果显示标题、短摘要、日期与证据数量。打开详情后能返回之前的搜索、筛选和滚动位置。

### 5.9 询问

采用面向个人记忆的检索界面：问题输入 → 时间范围/检索方式 → 结论 → 可点击证据。查询历史与保存的问题可以继续追问。

本地查找与外部 AI 解读的触发动作清楚分开。显示本次问题、检索范围和数据覆盖；切换日期或问题时旧回答不能静默套到新上下文。请求失败保留问题和本地结果；没有证据用“未找到记录”，不能回答“你从未去过”。

### 5.10 进展

把七张等大数字卡重组为：周期与覆盖说明 → 2–3 个主要趋势 → 紧凑对照表 → 支持变化判断的记录。

每张趋势图显示有效样本天数；缺失天断线或留空，不补零。对照采用同长度窗口，明确是否包含尚未结束的今天。采集覆盖差异显著时优先说明不足，不把新增采集天数当成个人进步。

心情、工作、学习与目标分别呈现；可选评分须可解释计算口径和证据。避免一个综合“人生分数”。

### 5.11 数据库

顶部日期、搜索、类型与来源筛选；主体使用原生表格，固定列标题、排序、分页/分批加载。明确总数、当前展示数量和截断范围。点击行查看详细字段、原文、来源标识、导入时间和关联记录。

默认展示可读字段；技术 ID、原始 JSON、调试信息放在详情。保持只读入口清楚，避免与修改原始证据混淆。

### 5.12 数据源与设置

数据源按应用活动、浏览、位置、健康、照片、日历、手动导入等类别呈现；未实现的连接器标记规划中，不能展示成已可连接。每个已支持来源显示连接、授权、最新成功时间、覆盖日期与失败原因。权限已允许不等于有有效数据。

设置保留四组：记录与采集、AI 与模型、隐私与数据、外观与应用。使用一致表单行，每行一个设置和简短解释。长文件路径显示文件名与查看位置入口；完整路径在展开详情中。

自动采集与自动 AI 分析建议提供清楚的独立控制与发送范围；首次配置模型应有成功、失败和未测试状态。删除、备份恢复和缩短保留期前准确说明作用范围。跨库保留政策尚未统一，应作为产品实现任务单独处理，不能靠一个笼统标签暗示已完成。

## 6. 完整交互状态

| 状态 | 用户应看到 | 可执行动作 |
|---|---|---|
| 初次使用 | 尚无数据，说明最小接入路径 | 接入一个来源或写一条记录 |
| 历史日无数据 | 指明所选日期；没有记录不代表没发生 | 查看相邻日期、补充记录 |
| 来源部分缺失 | 保留已有内容，指出受影响模块 | 查看来源、补充或稍后处理 |
| 来源过期 | 最后有效日期和当前缺口 | 同步、重新导入 |
| 本地加载 | 稳定布局与轻量加载占位 | 不阻塞导航 |
| AI 生成中 | 本次任务、范围、可取消状态 | 取消；继续查看事实 |
| AI 失败 | 简短原因，保留问题和本地结果 | 重试或改用本地检索 |
| 保存失败 | 输入仍在、明确未保存 | 重试、复制内容 |
| 待确认推断 | 判断与证据一起出现 | 确认、修改、暂不处理 |
| 草稿未保存 | 草稿提示和恢复入口 | 继续、保存、确认丢弃 |
| 筛选无结果 | 当前筛选条件 | 清除条件 |

草稿至少跨页面和跨日期保留；跨重启恢复需要加密草稿持久化，当前内存缓冲不能宣称支持。日报与 AI 回答按日期、问题和请求标识归属，迟到的结果不能覆盖新上下文。

## 7. 无障碍与动效

- 正文、关键状态和可操作文字不低于本方案字号下限；普通文字对比度验收目标至少 4.5:1，大文字与关键非文本控件至少 3:1。
- 提高对比度、减少透明度、浅深色主题分别检查。颜色不得独自表达成功/失败或正负趋势。
- 图标按钮具有名称；所有核心路径支持 Tab、Return、Space 和 Esc。焦点顺序随布局保持可预测。
- 图表提供文本摘要和数值读取；未知与零在视觉、朗读中都区分。
- 交互过渡约 120–180ms，面板约 180–220ms；减少动态效果开启时弱化或取消位移动画。

## 8. 实施顺序

| 阶段 | 主要交付 | 当前状态 | 完成依据 |
|---|---|---|---|
| P0 可读性与布局 | 字体、色彩、表面、按钮、页面容器、工具栏安全区域、侧栏状态布局 | 新增“窗口大小”菜单，可设 960×640、1280×800、1440×900；三档均在真实窗口应用，AX 列宽与目标相符。960/1280 用右侧 Inspector 浮层，1440 使用并排 Inspector；Today、Timeline、复盘、设置及数据库均无已观察到的横向溢出 | 首页/时间线/设置在三档尺寸无重叠、横向滚动和关键文字裁切 |

## 9. 最终验收清单

- 960×640、1280×800、1440×900 三种逻辑窗口尺寸；浅色与深色；证据详情打开与关闭。
- 首页十秒内能读出当天重点、数据覆盖和下一步动作；这是目标，须由实际体验验证。
- 普通阅读不依赖 8–10pt 关键文本，不出现浅灰文字叠加过低透明度。
- 同类页面标题、正文左边界、工具栏和按钮一致；每个控件产生清楚、可观察的结果。
- 日期在左侧统一选择；历史数据、页面标题、查询与详情日期一致。
- 同屏统计数字的来源、截止时间与计算口径一致或明确区分。
- 从摘要或查询结果到原始证据最多两次进入详情操作；能返回原来的位置。
- 不以零代替未知，不把应用分类时长等同效率，不把缺失样本连接成连续趋势。
- 无数据、部分数据、旧数据、加载失败、AI失败、保存失败都能完成下一步。
- 每轮交付包含改动前后同尺寸截图、交互复测记录及当前 Xcode Beta 构建验证；不以单元测试替代视觉验收。

## 11. 本轮实测记录

- Xcode Beta：打包成功，186 个 XCTest 通过，0 失败；新增 SQLCipher framework 嵌入、运行路径与签名检查。
- 草稿：停止输入后以 AES-GCM 加密写入本机 `journal.state`；测试覆盖跨重启恢复、备份 Codable 兼容、正式保存后清理，以及存储路径不可写时编辑内容仍保留、状态提示失败。该异常测试只用临时目录，不读取或修改真实日记。
- 事实库安全：legacy 与 V2 SQLite 使用 SQLCipher；临时库测试覆盖密文文件无普通 SQLite 头/明文标记、正确 key 重开、错误 key 拒绝、WAL 无明文、legacy/V2 迁移、迁移中断回滚、加密快照导出/恢复。真实两份数据库已迁移，行数与迁移前基线一致，数据概览页可读。
- 备份恢复：完整加密备份包含 legacy 与 V2 加密数据库快照；恢复前校验两者。开始切换前会持久写入 AES-GCM 事务日志，记下旧 SQLCipher 快照、足迹、`journal.state`、导入快照路径和追踪开关；成功提交前同步关键文件，启动时先重放日志恢复旧状态，失败时保留日志并阻止数据页面启动。临时数据测试覆盖真实 legacy/V2 密文快照、足迹和本地文件的中断恢复，以及验证失败后保留日志；未对用户真实备份做破坏性恢复。密钥当前仅本机可用，跨设备恢复/轮换仍需设计。
- 实窗走查：Today、Timeline、Daily Review、Health、Footprints、Work & Learn、Memory、Ask、Progress、Database、Sources、Appearance；历史日期会改变 Daily Review 的统计窗口；Ask 的地点问题无证据时明确返回未找到。
- 最新开发包实窗复查 Daily Review：评分与日期标签无裁切，缺失评分仍明确为未知；验收后返回 Today。
- “窗口大小”菜单的 960×640、1280×800、1440×900 三档均已在实窗选择，原生 API 直接设置内容尺寸；AX 列宽响应，960/1280 详情为浮层、1440 详情并排。Today、Timeline/Inspector、Daily Review、Settings 无横向滚动或裁切；数据库在 960 与 1440pt 无横向溢出。
- Inspector 响应式实测：960pt 下侧栏+主区约 960pt，详情浮层打开后时间线仍可操作，Esc 收起并恢复原行 AX 焦点；1440pt 下恢复并排详情。
- 证据详情：在新构建的实际窗口中，从 Today 时间线预览按 Tab 聚焦事件后，Return 或 Space 打开右侧 Inspector；Esc 关闭后 AX 焦点回到同一事件。显式关闭按钮也正常。⌘K 命令面板、⌘N 快记空白入口及 Esc 关闭也已实测，未写入测试内容。
- 最新构建烟测：左侧前一天/回到今天切换会同步更新时间线日期；点选事件打开证据详情，Esc 关闭后焦点回到原事件；完成后恢复 Today 与当前日期。
- ⌘K 命令面板键盘回归：查询有多个结果时，搜索框接收上下键并移动高亮；Return 执行当前高亮项。实窗以“足迹”筛选并打开第二个结果，避免只会执行首项。
- 全局键盘导航：旧快捷键⌘1 Today、⌘2 记忆、⌘3 询问保持不变；新增⌘4 时间线、⌘5 每日复盘、⌘6 健康、⌘7 足迹、⌘8 学习与工作、⌘9 进展、⌘0 数据库、⌘⇧D 数据源，设置仍是⌘,。通过新构建的 Xcode Beta 窗口实际触发全部路由；⌘1 回到 Today。唯一性有自动测试覆盖。
- 搜索键盘入口：⌘F 在记忆页将焦点送到“搜索你的过去”，在询问页将焦点送到查询框并选中当前问题；两条路径在新构建真实窗口验证。系统键盘导航关闭时仍可直接调用，不需改全局偏好。
- 数据库长列表：实测 9 月 22 日有 133 条原始事件，默认页为 94–133；“较早”翻到 54–93，“较新”返回最新页。改日期、切数据表、刷新都重新定位到最新页；4 项测试验证 1,620 条的分页覆盖无重漏、空/短列表和记录数缩小时边界。
- 备份恢复失败路径：故障注入模拟活动恢复失败及 legacy 已替换后 V2 恢复失败；确认实时活动、两份数据库和 `journal.state` 回滚。活动目录以临时加密文件集替换，并在成功/失败后恢复原追踪开关；确认对话框已说明校验与回滚边界。
- 跨库持久恢复日志及启动错误门控已通过临时数据测试；未在真实用户数据库上强制结束进程或断电，也未执行真实用户备份的破坏性恢复。
- 健康心情表单：无记录时默认滑块位置显示为“未选择”，保存按钮禁用；明确调整后按钮启用，取消后状态仍为未知。0、50、已有分数修改/取消均由 4 项回归测试覆盖；烟测未保存任何心情。
- 视觉修正：将 Timeline 类别标签移到事件标题旁，并在重建后的开发版截图确认；“写日记”入口展开编辑器，普通进入 Timeline 保持收起。复盘节律图评分/日期标签由 10pt 提至 11pt，移除缺失评分破折号的额外淡化，并避免 9pt 容器裁切。
- 深色主题实测覆盖 Today、Timeline 和 Inspector，语义文字、面板层级与蓝色焦点边框可辨；随后恢复浅色/标准密度。
- Ask：搜索框边界、建议问题及证据说明字号已调整，并在真实窗口确认无溢出。
- 窗口复查：三档尺寸均通过原生预设实窗选择；紧凑/标准下详情浮层、宽屏下并排。截图位图不是逻辑尺寸读数，但三档内容尺寸由 NSWindow API 明确设置。
