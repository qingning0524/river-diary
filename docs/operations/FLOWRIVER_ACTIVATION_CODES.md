# FlowRiver 账号登录与权益兑换

## 用户流程

首次打开 iOS 或 macOS 版本时，用户使用邮箱收 8 位验证码登录；未注册邮箱在验证成功后自动建立账号。账号会话保存在系统钥匙串，access token 短效，应用用 refresh token 轮换续期。服务端只接收账号、邮箱验证、设备会话和权益信息，不接收日记正文、位置、健康记录或同步密钥。

用户进入设置页“River Diary 账号”/“账号与权益”输入兑换码。兑换成功后，服务端把一次性兑换记录与 `riverdiary_premium` 权益写在同一事务中。相同账号后续在已登录设备上查询权益状态。兑换码不会在 iOS 与 macOS 间共享；账号权益会。

设备上的本地资料在首次登录后绑定到该账号。退出后可用同一个账号重新登录；当前版本检测到另一个账号时会拒绝打开这份本地资料，避免账号切换后误读或混用。当前没有提供本地 profile 导出/切换向导，不能通过卸载/清缓存来代替安全迁移。

## 管理员后台

打开 `https://admin.flowriver.xyz` → “激活码与权益”：

- 生成随机码，或将已有码按行导入。
- 每批选择产品权益代码、永久（天数为 0）或 N 天，以及可选的兑换截止时间。
- 新生成的完整码在页面内立即出现，可下载 CSV；离开此页/刷新后，数据库不会永久保存明文。
- 批次列表显示总数、兑换数、可用数。码列表只显示尾号、状态和兑换账号 ID。
- 删除按钮对未使用码执行带审计记录的撤销。已兑换码保留历史并不可删除；该操作不会撤销已授予的权益。
- 敏感写操作要求管理员重新输入密码和新的 TOTP 验证码。

为应对管理员页面网络中断，生成响应会使用独立密钥加密并最多保留 15 分钟，按相同幂等请求恢复同一批明文码；清理任务到期删除加密响应。之后只能查看尾号，不能取回完整码。

## 权益规则

- 每个兑换码仅能成功兑换一次，兑换账户记录不可改写。
- 永久权益不会被后续限时码缩短；限时码在当前限时权益有效期后顺延。
- 未兑换码可撤销；已兑换码保留，便于审计与支持查询。
- 代码当前建立并查询账号权益状态，但 River Diary 尚没有以此字段控制具体高级功能的产品门禁。接入功能开关时，客户端必须以服务器的有效权益状态为准，不能因本地缓存或未成功的兑换响应提前放行。

## 相关接口与迁移

- `POST /v1/auth/email/start` 返回通用提示和 opaque `challenge_id`。对所有格式有效的邮箱都使用同一响应形状，不透露该邮箱是否已经注册。
- `POST /v1/me/activation-codes/redeem` 需要 Bearer 会话和 `Idempotency-Key`。
- `GET /v1/me/entitlements` 返回当前有效/到期的产品权益。
- 管理员接口见 `server/api/admin-openapi.yaml`。
- 新数据库结构由 `0003_activation_codes.sql` 增量迁移。应用自动应用迁移；升级前仍需执行常规数据库备份流程。

## 账号同意说明

首登界面会要求用户勾选账号服务与隐私说明。服务端为每次新账号记录当前部署的 `TERMS_VERSION` 和 `PRIVACY_VERSION`。生产发布前应将正式条款与隐私政策发布、审阅并设置对应版本；内置界面文案只说明本首期 API 的数据范围，不代替正式政策文件。
